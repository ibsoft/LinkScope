# Endpoint Protection V65 — isolated live protection lab

Step 05 adds **Run isolated protection lab**. The full automated suite can optionally include it using **Include isolated live protection lab (canary comparison and EICAR)**. This option is unchecked by default because it creates an actual antivirus test file, can trigger production alerting and may retain a real sealed quarantine item. Use only a disposable test directory in an isolated VM/test environment. Select a saved leaf response directory, e.g. `C:\Apache24\LinkScope-Ransomware-Test` rather than `C:\Apache24` when both are authorized. The server rejects a parent with nested saved response paths. No arbitrary command, new permission, production policy mutation, or process termination is added. Only administrator requests with the existing CSRF check can start or retrieve the short-lived single job; the same administrator must retrieve its result. The request creates a local server job; the browser polls with its exact job ID. Policy changes or shutdown stop further test activity and cleanup is attempted using original identity only.

## What the tests establish

* Disposable canary comparison: a uniquely named file is created exclusively using the embedded harmless template, baseline SHA-256 is read from disk, one known byte is changed, and the changed on-disk hash is verified using the shared production comparator and the exact expected altered bytes. The separate lab incident is written to the incident database, explicitly as a lab comparison. The handle is delete-on-close; absence is checked. This does **not** enroll a new production canary or prove normal watcher detection of enrolled canaries. Existing enrolled files and baselines are never changed. The true enrolled-canary watcher exercise remains manual and Not tested.
* EICAR: a single harmless standard 68-byte test sample is created with a unique GUID name, actual contents and original file identity verified. The normal scanner must generate fresh, matching malware and quarantine incidents after the database watermark; the test does not call quarantine directly or inject a verdict. The production quarantine path still requires its authenticated ClamD re-scan. The lab checks the EICAR verdict, exact path/hash, ordered incident sequence, receipt ID/state/path/hash/timestamp, actual sealed payload read and in-memory DPAPI decryption/hash, and original absence before declaring quarantine verified. If the normal scanner does not produce evidence in the 15-second observation window, another product intercepts the sample, the receipt is incomplete, or a request fails, the result is Review or Not tested. A delayed detection can happen after the bounded test. Never disable another antivirus to make this pass. If cleanup is needed the service only deletes the original matching identity and exact EICAR hash; a changed file, failed cleanup or other unverified condition is reported for inspection. The sealed receipt remains in the normal vault for inspection and administrator-controlled deletion. Source of scanner execution may be real-time or baseline; the test does not independently prove watcher delivery.
* Production incident attribution is labelled **Awaiting production incident evidence**. When no production incident has been observed, the report marks that measurement Not tested, not a false failure or pass. Actual production termination remains Not tested. No production response rules changed.

The dashboard requires structured proof for every Pass in the isolated lab, including the fixed known hashes, path and run identity, incident watermark and sequence ordering, receipt time and cleanup. Absent or contradictory evidence remains Review. The automated suite preserves initial and final telemetry and rechecks after all chosen probes. Results remain session-local; export before reload. The job result is held in memory until a subsequent lab starts or the service restarts.

## Validation and limitations

Five targeted regression scripts passed in Linux: `validate_protection_lab_v65.py`, `validate_external_writer_v64.py`, `validate_automated_suite_v59.py`, `validate_guided_test_center_v58.py`, and `validate_live_audit_v56.py`. They cover static source assertions, C# delimiter balance checks, JavaScript proof logic and real Chromium with mocked service responses. JavaScript syntax checked. Native C# compilation, Windows file I/O, actual ClamD verdicts and actual quarantine execution are **not verified** here. This release is not a production certification. The full historical regression suite has not been run.

Build using `Rebuild-VisualStudio.cmd Release`, then upgrade with Setup as normal. No lab file is created by Setup.
