# NTFS USN Journal monitoring (V11)

Upgrade from V10 using `Rebuild-VisualStudio.cmd Release`, then select Upgrade / repair in LinkScopeSetup.exe. Do not remove ClamAV or existing canaries. Under Settings → Endpoint Protection, enable real-time protection and configure `C:\` and `D:\` (one path per line). Start in Monitor mode. Journal collection is automatic for the configured local drive letters; no extra switch is required.

## Design

The installer registers `LinkScopeUsn`, a separate LocalSystem service with a fixed installed binary path and a fixed `--usn-service` entry point. The existing LinkScope web/monitoring service remains LocalService. The journal helper accepts only a drive letter and journal ID/cursor, returns bounded metadata batches through a local named pipe with a service-SID ACL, and never reads file contents, changes the journal or executes commands. The client verifies the pipe server PID against SCM. The helper is stopped before an executable upgrade and removed during uninstallation; failure to start the helper leaves existing monitoring available. No filesystem permissions outside the existing installer scope are changed by this feature.

The reader queries and reads existing fixed NTFS journals using FSCTL_QUERY_USN_JOURNAL and FSCTL_READ_USN_JOURNAL. It processes V2 records and resolves the recorded parent ID to a current path where possible. It handles content changes, creates, deletes and both rename sides; it does not preserve exact historical paths after parent moves/deletions. It coalesces paths into a durable SQLite queue and commits the per-policy/volume journal ID and cursor in the same transaction. An interrupted scan attempt is retried on restart if not acknowledged. First activation starts at the current journal tail and requests the existing full scan. Scope/exclusion changes start a new coverage scope; old scope checkpoints and pending work are discarded. Journal reset, wrap or unresolved parent IDs generate coverage warnings and request reconciliation. If the journal is inactive, access fails, the filesystem is unsupported or the reader fails, FileSystemWatcher and periodic scanning continue. The helper does not create, resize or delete a journal. Journal replay uses bounded batches and pauses on a full 8192-entry durable queue; no silent cursor advance on queue pressure.

The Endpoint Protection dashboard shows per-volume Live, Replaying, Fallback or Backpressure status, details and durable pending scan count. Live refers to journal ingestion, not a guarantee of complete antivirus coverage. The existing file size, traversal (100,000 entries per full scan), access, exclusions, reparse-point rules, scan rates and restricted automatic response scopes remain. The USN reader cannot attribute changes to a process, cannot reconstruct deleted file contents, and cannot guarantee recovery beyond NTFS retention. Scan work is acknowledged after an attempt; scan errors remain in existing findings and periodic reconciliation is still needed. The service does not bypass filesystem ACLs for malware scanning. High-volume systems may generate a backlog; monitor status and coverage warnings.

## Windows acceptance test (not executed in the development container)

1. Rebuild and run the synthetic parser fixtures: `bin\Release\LinkScope.exe --usn-self-test`.
2. Upgrade normally. In elevated PowerShell, check `Get-Service LinkScope,LinkScopeUsn` and `sc.exe qc LinkScopeUsn`. Verify the original service stays LocalService and the reader is LocalSystem.
3. Query `fsutil usn queryjournal C:` and `fsutil usn queryjournal D:` if D is NTFS. Do not create or delete journals as part of testing.
4. Configure both drive roots and real-time monitoring. Confirm volume status becomes Live or Replaying in the dashboard. Use a harmless test file under a writable, non-excluded folder; create, modify, rename and delete it. Check existing activity telemetry and pending queue. Check that the normal canary status is unchanged.
5. Stop LinkScope (not the journal reader), create and modify a harmless test file, restart LinkScope and confirm replay using the retained checkpoint; check that pending work drains. Stop the journal reader and verify explicit Fallback, then restart it and verify replay. Repeat using an excluded path and a non-NTFS volume if available.
6. Upgrade and uninstall in a test VM; verify the reader is stopped before replacement and removed on uninstall, while the existing history and canary originals are preserved.

Portable checks: `python tests/validate_usn_journal.py` covers actual SQLite statements, rollback, persistence, deduplication and wiring. It does not execute Windows APIs or compile C#. The native parser fixtures are included but not executed here. Windows 11 service installation, ACLs, IOCTLs, and real-volume performance remain unverified.
