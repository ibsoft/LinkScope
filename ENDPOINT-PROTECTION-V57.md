# V57 — Official daily definition version comparison

V56 classified an engine's official daily database solely by its reported publication date (72 hours). On the reported host, ClamD and its signed daily.cvd both reported version 28194, and the fresh official current.cvd.clamav.net TXT advertisement also reported 28194. This is not a missing database update.

V57 compares the engine-reported daily version to the official DNS-advertised daily version. Publication age remains visible. DNS TXT field 3 is the daily version; field 4 is the advertisement timestamp (Unix seconds). Advertisements older than 3 hours, more than 5 minutes ahead of the clock, or malformed are rejected. The ordinary Windows resolver is used; this is advisory version information, not cryptographic database validation or proof of DNS authenticity. DNS failures fall back to the existing conservative 72-hour age policy. If the engine version is ahead of the advertisement, the comparison is inconclusive. The standard installation also checks the daily archive header on disk; a newer disk version prevents a ready result until reload. Disk header inspection is advisory only and does not prove that all third-party databases are loaded.

The endpoint scanner schedules a single background DNS task per process, checks every 10 minutes, and never waits for DNS. Setup and the maintenance worker may wait up to 3 seconds per readiness evaluation. An unresolved query is not replaced by concurrent queries. The first telemetry sample may still carry an age warning pending DNS completion and the next engine probe. The user can see the comparison in Maintenance, Test Center and detailed endpoint metrics. Setup records publication age and version evidence in its debug log. The 72-hour threshold is not removed: it remains the fallback when the official advertisement cannot be checked, and old publication dates are explicitly disclosed even when the version matches.

An unchanged old database no longer triggers reload solely due to the prior age warning. Reload is requested when database contents changed or the daily archive header is newer than the running engine. Provider cooldowns, FreshClam's updater, scan cache rules, quarantine, containment, audit policy and ACL provisioning remain unchanged. No credentials or third-party URLs are queried or exposed by the DNS comparison. DNS is not used to authorize any security response.

Build using Rebuild-VisualStudio.cmd Release, upgrade using the resulting Setup and recheck Maintenance. Native compilation, Windows DNS API behavior, signed archive verification and live FreshClam integration must be tested on a Windows machine. Portable checks include actual Chromium browser tests against fixture data and source checks, not native execution. The reported DNS/version values are used only as self-test fixtures; production version values are dynamic.
