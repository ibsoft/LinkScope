# Endpoint Protection V32 — release candidate

## Evidence
Based on the 27 November 2026 22:54:09 snapshot and V31 source archive. ClamAV reports online, 917 clean checks, 612 baseline file verdicts, 839 SYSTEM-assisted checks, 51 durable pending entries all in cooldown, no watcher backlog or queue overflow, 89 routine outstanding coverage records, 91 total active scan issues and 22 size-limited baseline files. No active confirmed malware was reported. This is not proof of absence of malware. Historical transport failures remain visible; no later timeout than 22:42:18 is shown in this snapshot. No custom application root is shown separately in the supplied runtime scope; existing configuration support is preserved.

## Changes
The scanner and authenticated SYSTEM helper now recognize a typed reparse-boundary outcome, without following a junction, symbolic link or other unsupported reparse target. Confirmed boundaries are retained as coverage findings with no signature verdict; they are terminal for the current queue event rather than retried indefinitely. Scheduled reconciliation and subsequent events can inspect them again. Explicit protected paths and canaries retain their existing warning treatment; no automated containment is triggered solely by the new boundary classification. Existing fixed-canary verification remains unchanged. No new blanket exclusions, automatic permission grants, or changes to quarantine policy.

Size-limited verdicts now report the configured MiB cap and observed file bytes where available; the helper reply includes an additive size field. No limit is silently increased. Large files remain unverified. The dashboard separates coverage categories, durable ready and cooldown work, baseline traversal counts and the last finished baseline attempt from a successful complete baseline. The discovered pending path count is not an estimate of all remaining files. The existing 100,000-path traversal guard now creates explicit evidence if the scan aborts at that cap. The existing 8,192-entry privileged directory enumeration cap still applies. These limits require further design work for very large profiles. Journal gap diagnostics include unresolved record counts and acknowledge that protected-scope membership is unknown, rather than assuming every unresolved record belongs to the protected profile. The gap itself is not cleared or hidden. No actual recovery of lost historical USN evidence is claimed.

## Build and deployment
Extract into a clean directory, back up installed configuration and endpoint database, build using `Rebuild-VisualStudio.cmd Release` on Windows with the project's required toolchain, and use the newly generated installer on a test endpoint. Both the main service and SYSTEM helper must be upgraded together. No executable is shipped. Existing user-profile and custom-folder policy stays intact. The UI can still show an unversioned build when built from a ZIP outside a Git checkout; verify the exact archive/build output independently.

## Acceptance checks
On a test endpoint, inspect a normal file under the user profile and an explicitly configured custom folder. Verify a clean signature verdict, then test an exclusively locked harmless file, release it and verify an eventual verdict. Test a junction pointing outside the configured scope; verify no content traversal, no clean verdict and persistent boundary diagnostics. Verify that changing a junction to a normal folder or file permits a new inspection when an event/reconciliation occurs. Test a file just above the configured cap; verify size details and no clean verdict. Verify canary integrity detection and the existing signed verdict and quarantine workflow using authorized test procedures. Validate journal replay after a service restart and confirm that a complete reconciliation is required before clearing a gap. Inspect ClamD logs and CPU/RAM on the host. Do not clear the alerts or disable primary AV to manufacture a passing result.

## Validation and limitations
38 of 45 portable source/SQL/UI regression scripts passed. Seven failed or timed out: account menu icons and header alignment timed out; navigation local browser access blocked; CSS layout assertion, missing Font Awesome notice, provider CSS assertion and signature-schedule roundtrip failed. The latter three were reproduced on V31; the CSS assertion was reported previously. See ENDPOINT-TEST-RESULTS-V32.txt. JavaScript syntax checked successfully. Native C# compilation, Windows service behavior, ClamAV integration, process attribution and resource/load benchmarks remain unverified. ClamAV timeouts, true full-profile coverage (including locked and oversized files), volume-wide unresolved journal records and pre-execution protection are not solved. Do not deploy as production-certified software. Primary antivirus should remain enabled.
