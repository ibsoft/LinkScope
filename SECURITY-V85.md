# LinkScope V85 — security hardening release candidate

## Scope and evidence

Reviewed the supplied V84 source, focusing on the HTTP parser and listener, access/session and account handling, API scopes, outbound AI/SMTP/SIEM/syslog clients, SQLite, installer ACLs, evidence/response boundary, audit storage and vendored browser library. This is a focused source review and targeted implementation, not a penetration test, ASVS certification, exhaustive code audit or assertion of no exploitable vulnerabilities. The latest source is V85; the underlying detector/response and installer implementation files are byte-for-byte unchanged from V84. Build and live service acceptance tests on Windows are required. No GPU work.

References: OWASP Top 10:2025 (https://top10.owasp.org/2025/), OWASP API Security Top 10:2023 (https://owasp.org/API-Security/), OWASP ASVS 5.0 (https://asvs.owasp.org/), OWASP Cheat Sheet Series (https://cheatsheetseries.owasp.org/), and NIST SSDF (https://csrc.nist.gov/Projects/ssdf). These are risk/verification references, not certifications.

## Changes implemented

* Web request token buckets: 30 requests/sec per source IP with 100-request burst; global 120/sec with 240-request burst; bounded 1,024-peer table, idle eviction after 300 s when full. Existing connection cap 24, new cap 12 concurrent connections per source IP. Excess concurrency is closed before TLS; rate rejection returns 429. Existing 15-second absolute connection deadline and bounded parser preserved. Rate limit operates after parsing; use firewall/reverse-proxy capacity controls for network-layer DoS. Do not trust forwarding headers; NAT clients share a bucket.
* Session fixation defense: after successful login, revoke the previously supplied browser session identifier; a newly generated independent random identifier is returned. Other browser sessions are not revoked by a normal login. Credential/role revision invalidates affected sessions as before.
* Authenticated state-changing POSTs (except idempotent logout) require `X-Request-Nonce`, a 32-character lowercase hex 128-bit random value from Web Crypto. It is consumed after session, CSRF, origin and role checks, before mutation. Duplicate values return 409, missing/invalid values return 400. Each session retains up to 4,096 unique mutation nonces for its lifetime; exhausted sessions must sign out and reauthenticate. Login has existing password/MFA replay controls and logout invalidates its session. This prevents exact nonce replay in a live session, not misuse of stolen credentials or bearer tokens and not business-level exactly-once execution. A fresh nonce can authorize a separate operation. Review actual state after ambiguous network failures. Existing `/api/v1/system` is GET-only and bearer tokens remain reusable until expiration/revocation. Refresh pages opened before upgrading; private cookie-based automation clients must send a fresh nonce per mutation.
* HTTPS, SMTP TLS and TLS syslog use TLS 1.2 in the .NET Framework 4.8 service; managed HTTPS certificate revocation checking explicitly enabled, no acceptance callback bypass, default platform chain/hostname validation. TLS 1.3 is not implemented. TLS versions/cipher suites and trust policy must also be managed by Windows/Schannel. TLS 1.2 is retained for compatibility. HSTS applies to HTTPS (one year; no includeSubDomains/preload because the service does not control every subdomain). CSP and existing headers preserved; added cross-domain-policy denial. Local-only HTTP remains a compatibility bootstrap unless the production transport policy is activated.
* Outbound guard checks all DNS answers and rejects link-local, unspecified, multicast, selected cloud platform/metadata addresses and unexpectedly loopback-resolving DNS names. Explicit localhost/private enterprise integrations remain supported. SMTP/syslog connect directly to validated IPs. Managed HTTP clients perform preflight DNS validation, retain no redirects and in strict policy mode bypass configured proxies. DNS preflight does not pin the actual HTTP connection, does not cover every possible metadata endpoint, and is not complete SSRF protection. Use external network egress allowlisting and trusted DNS; restrict outbound SMB/UNC, FreshClam and other subprocess network access separately. No automatic changes to Windows firewall or endpoint scan/response policies.
* Optional local-administrator-controlled production transport policy enforces HTTPS listener, permanent builtin administrator credential, TLS/STARTTLS SMTP, HTTPS Seq/Elastic/AI and TLS syslog, with explicit destination hostname/port allowlist. It rejects direct plaintext Wazuh TCP/UDP while strict mode is active (use a TLS relay or retain compatibility mode until migration). Checks at startup, configuration save and managed outbound calls, including test sends. No implicit migration or feature deletion; administrator activation required.
* Audit fields escape CR/LF and control/directional separator characters before parameterized storage; existing audit history is unchanged. Audit writes are not immutable against a compromised privileged service or host administrator. No bearer values/cookies or request bodies are added to audit. Remote independent audit storage and alerting on audit failures remain release requirements.
* Vendored dependency hash inventory and optional advisory checker added. Source banner identifies pdf-lib 1.17.1 and bundled dependency names; exact bundled versions, trusted upstream equivalence, and external/runtime patch levels have not been independently verified. Offline hash test does not establish safety/provenance; online check queries OSV only for exact inventoried versions, reports incomplete coverage with exit 2, fails on advisories/errors (exit 1). No automatic third-party updates. `python tools/Check-Dependencies.py --online` must be run in an approved internet-connected release environment; review Windows/ClamAV/browser vendor advisories and verify signatures separately.

## Activate production transport policy (Windows administrator)

1. Upgrade normally. Do not enable a production policy until certificate and integration validation has been completed. Set a permanent administrator password (and enroll MFA), select HTTPS in Settings and restart. Use a valid hostname-matching certificate in the Windows local-machine store, trusted by each client. Do not bypass browser certificate warnings. The installer-generated self-signed certificate is not automatically a trusted public-CA certificate. Prefer a trusted internal/public CA. Confirm service-private-key access, certificate expiration and Schannel policy.
2. Migrate enabled SMTP/AI/HTTP SIEM/syslog integrations to encrypted endpoints. If direct Wazuh TCP/UDP is currently enabled, migrate to a supported TLS-capable relay before activating this policy. Configure trusted DNS and operating-system/network firewall egress controls for approved services, with metadata/link-local blocks. Allow DNS and the required ClamAV update endpoints independently. A host:port allowlist alone cannot prevent DNS rebinding or arbitrary paths on an allowed host. The strict HTTP clients use direct connections, not an outbound proxy; deployments needing a proxy must explicitly design and test a compatible alternative.
3. Edit `security/production-transport.example.json` to the exact enabled destination host:port values. Use IPv6 brackets, e.g. `[::1]:443`. Do not use wildcard destinations; an empty array permits no managed outbound integrations. Copy the file as `%ProgramData%\LinkScope\production-transport.json` (NOT inside `settings`). Only Administrators/SYSTEM may modify it; the LinkScope service SID may read it. Verify the file inherits the installer-protected root ACL and that no writable ACE or reparse point undermines it. Do not copy the example domains verbatim. The file is optional, not created automatically by Setup.
4. From an elevated PowerShell, run `& "$env:ProgramFiles\LinkScope\LinkScope.exe" --check-production-policy`. This returns 0 for valid configuration, 3 if no policy exists, 1 for invalid configuration. It does NOT validate the live certificate or connectivity. Verify output and `$LASTEXITCODE` before restarting. The policy is loaded at process startup; invalid or incompatible policy prevents the entire monitoring service from starting. Schedule a maintenance window, preserve the current configuration and test on a noncritical server first. Rollback: remove/rename only the policy file as an administrator and restart; do not reset endpoint data.
5. Restart LinkScope, inspect Service/transport-policy log entry, verify health and all existing protection features. Run live acceptance tests. No claim of production-ready security until these pass.

## Acceptance gates

Build with `Build-VisualStudio.cmd Release`; run the compiled `LinkScope.exe --self-test` in a disposable Windows lab. Added native test cases for nonce duplicate and missing header, rate limiter, special-use DNS/IP destinations and strict allowlist/TLS validation. Required Windows integration: trusted/untrusted/expired/wrong-host/revoked cert cases; plaintext remote rejection; strict-policy startup and rollback; direct/proxied DNS/metadata egress cases; POST missing/invalid/replayed nonce and CSRF; old session revoked; account roles, IDOR, scoped/expired/revoked bearer tokens; HTTP malformed/oversize/slow clients; sustained and burst load; secrets absent from API/logs; SQLite/ACL and file/junction race tests; independent audit backup/retention; all existing EICAR, web script quarantine, canary, USN, ransomware, installation/upgrade and reporting acceptance tests. Test with actual Windows service identity, not only an administrator console. Perform independent penetration test and security review before a critical production rollout.
