# V53 — Independent permission repair

The reported service SID exists, but neither Security channel nor directory ACLs show a dedicated service rule. No backups were returned by the administrator's listing. The data does not establish whether the repair wizard was launched or which operation failed.

V52's all-or-nothing preview could block independent channel repair if folder eligibility, pinning or audit ACL access failed. V53 previews each of the channel, audit and access sections separately; only successful previews are eligible for the subsequent administrator confirmation. Failed application of one approved section does not prevent attempts for the other approved sections. Each failure includes the operation name and exception in the wizard and elevated setup log. The wizard also logs opening and discovery status. Manual selected repairs likewise report independently. Scope errors distinguish missing saved paths, outside-scope paths, exclusions and canary targets.

No new permission types, service elevation, automatic global audit policy changes, process termination grants, or changes to the antivirus engine. All original scope, directory pinning, pre-write backups, rechecks and conflict-aware rollback controls remain. Effective service access is not inferred from ACL descriptor readback. An explicit confirmation is mandatory; the default response is No. Repairs may be partially applied; inspect logs and individual backups before retry or rollback.

For lab use, configure only the dedicated test directory as the response path (retain the parent as a protected monitoring path). Open Setup > Endpoint permission repair, select the test directory, use Automatic repair, confirm eligible steps, inspect the final per-step summary, restart LinkScope at a suitable maintenance time, and rerun Test Center. If still blocked, send the latest *endpoint-permissions*.log from the elevated setup log folder. If no folder is selected, channel repair can be previewed and approved independently. No repair is performed merely by upgrading.

Native Windows compilation, ACL writes and service-access verification not executed here. V53 supersedes the V52-specific static repair fixture; historical reports are preserved. Full historical suite not rerun.
