# Endpoint Protection V40 — corroborated extended ransomware observation

V39 defaults to 50 distinct observed content changes and at least three qualifying entropy increases within 60 seconds. Observations are collected when files are inspected, not at the moment of writes, so scanner latency can cause a burst to be split across windows. The reported failure has not been reproduced on Windows; missing initial file identity baselines, excluded paths, locks, or unprocessed work can also explain it.

V40 preserves the existing rapid detector and automatic response gates. It adds a separate detection-only warning when five distinct paths in the same immediate directory show qualifying content and entropy changes over a rolling 300-second scan-observation window. This is a fixed supplementary rule, not a change to the user's existing rapid threshold. It does not trigger containment even in contain mode. When the rapid warning is active the supplemental warning is suppressed. Evidence is bounded, deduplicated case-insensitively and reset on policy changes and destructive history reset. The extended evidence is in memory, not persisted across restarts. Legitimate bulk compression/encryption may trigger it. It cannot detect all ransomware, particularly files that were already high entropy or have not been previously observed. No exclusions, engine settings, or protection paths have been changed.

Dashboard: File changes shows the configured rapid window and threshold; Extended entropy changes shows the peak distinct count in one directory during the extended window. ClamAV clean is compatible with a behavioral warning.

## Windows acceptance test

Use a disposable synthetic directory below C:\Apache24, in Monitor mode, and verify C:\Apache24 is an active protected root. Generate fresh low-entropy test files; confirm the individual files have completed initial inspection in Live file scan activity before modifying them using the previous safe simulation. Check that the modified files are inspected and the extended count rises. Look for Possible ransomware activity (extended observation) in active findings or recent history. If the rapid detector triggers instead, that is also a valid result. Ordinary file changes alone must not trigger either rule. Check that one repeatedly modified file or changes in unrelated folders do not satisfy the supplemental threshold. Restore or remove only disposable test files afterward. Do not modify real Apache configuration/log files or reset evidence to hide findings.

Portable checks and a native SelfCheck assertion were added. Native compilation and execution are not verified in this environment. No claim is made that the reported Windows failure has been resolved until the acceptance test passes.
