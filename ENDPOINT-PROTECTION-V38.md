# Endpoint Protection V38 — disk-aware background reconciliation

## Scope and upgrade
This is the complete V37 source plus V38 endpoint-only changes. Build `Rebuild-VisualStudio.cmd Release` in a clean directory, then install the new setup to update both LinkScope and LinkScopeUsn. The two services must be upgraded together because the scoped baseline request has an optional fourth field (NTFS stamp). V38 accepts legacy three-field requests; V37 helpers do not understand four-field requests. Existing settings and protection scope are retained. The SQLite schema migration adds a nullable stamp to the old cache table. New settings have safe constructor defaults; the existing cache policy key changes and the first reconciliation may be expensive.

## Resource defaults
* BackgroundReadMiB=10 (5–50 MiB/s). Paces the background entropy sample, SHA-256 and INSTREAM reads, including in the privileged helper; the 30 s base ClamD deadline gets a bounded 20 s background transfer allowance. This is a read pacing target, not a physical disk I/O or SSD-write cap. FileStream buffering, NTFS metadata, SQLite, other processes, ClamD and OS caching are not covered by the byte counter.
* Windows background thread mode is requested only around baseline work, and restored afterwards. Windows may refuse the priority change; byte pacing remains in effect.
* Real-time work, canaries and ready journal entries are handled first. Additional baseline steps are suppressed while ready queues have work. One in-progress scan is still synchronous and can delay subsequent work; this is not a preemptive independent scanner.
* Pause during high disk activity: enabled. Uses the Windows PhysicalDisk aggregate % Idle Time counter, sampled about every three seconds, pausing after two readings at or below 10% idle; resumes after two readings at or above 25% idle. A missing/unusable counter (including localized names) leaves byte pacing active, and the dashboard shows the diagnostic. This is a host-wide proxy, not a per-volume SSD/HDD meter. The pause does not change policy coverage or stop real-time/canary monitoring. An indefinitely busy disk can delay baseline completion indefinitely.
* Pause on battery: disabled by default; configurable. Real-time scans remain active.
* Existing baseline interval is retained; new configurations already default to daily. Existing cache expiration is seven days; no hit renews its age.

## Metadata cache policy
Settings > Endpoint Protection > NTFS metadata-only clean verdict reuse when verified (enabled by default). Only baseline files with a prior clean verdict, current verified ClamAV generation, matching policy, no outstanding per-file finding, and an existing matching content identity may skip file content reads. The same verified read handle must supply a valid NTFS volume GUID, volume serial, file reference, journal identifier and per-file change USN, file size, creation time, last write and NTFS change time. The current USN must be in retained journal bounds; journal metadata is checked before and after the file USN operation. Hard links, offline/recall files, reparse paths, unsupported volumes/record layouts, invalid handles, inaccessible metadata and journal gaps disable metadata reuse. The stamp is compared twice on the same held read handle. A fresh ClamAV verdict is the only way to establish a new timestamped cache entry; its stamp must also match before and after inspection. The cache hit updates baseline seen state but never clears security findings or counts as a fresh signature verdict. The helper authorizes the scope independently, validates the path, verifies its own engine generation and replies only with metadata and verdict; no file content returns through its pipe. Real-time and canary checks never use the metadata fast path. Hash-only reuse retains V37's content verification semantics. A changed stamp does not establish a changed hash by itself; the file is read and hashed, and the engine generation is rechecked before hash reuse. A changed hash, stale or unknown generation, expired cache, reset or other cache miss requires a new signature inspection. Disable this setting to require content hashing on baseline cache hits. This is not a kernel-level integrity guarantee or protection against privileged tampering. It is intentionally conservative and may yield few hits on busy volumes where journal entries age out or where volume queries are unavailable to the service identity.

Reference for native API semantics: Microsoft Learn, FSCTL_READ_FILE_USN_DATA (https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data) and USN_JOURNAL_DATA_V1 (https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-usn_journal_data_v1).

## Windows acceptance gates (not executed here)
1. Build both solution configurations and setup; run native self-checks. Upgrade both Windows services; inspect service start logs and verify the four new settings are persisted.
2. Compare a clean disposable NTFS scope's first baseline and second baseline under unchanged signatures. Check Metadata-only cache hits, Cached clean verifications, Fresh signature checks, and file activity details. A metadata hit must have no content read and must not increment fresh scans. If metadata is unavailable, confirm hash fallback instead. Verify legitimate modifications with restored last-write timestamps, replacement with same size, renames, journal recreation on an isolated test volume, journal wrap, and stale cache all cause hash or fresh scan fallback; never deliberately reset a production journal for this test.
3. Test clean and detection fixtures in an isolated test scope with primary antivirus enabled; verify real-time and canary scans bypass caching. Check cache invalidation after signature changes/restarts and both reset operations. Verify locked files remain unverified and pending. Do not remove existing protection or delete quarantine evidence.
4. Observe Resource Monitor during first and later baseline scans on an HDD and an SSD. Measure actual disk reads, latency, CPU, service responsiveness, queue age and SQLite writes. Test disk-pressure pause/resume, battery option and unavailable counter fallback. No performance measurements or native Windows compilation are available in this environment.
5. Review the full selected portable test log ENDPOINT-TEST-RESULTS-V38.txt. This is a release candidate, not production-certified.
