## Run the full suite

Rebuild using `Rebuild-VisualStudio.cmd Release`, upgrade with Setup, and open Endpoint Protection > Test Center. Select an existing disposable directory explicitly saved under Settings > Endpoint Protection > Test Center directories. The directory must be a protected, non-excluded leaf response directory with existing access. Choose **Run full security validation** and explicitly confirm that the selected directory is disposable and isolated. This includes the isolated protection lab. No default paths, ACL changes, executable authorization or policy expansion are introduced. A directory can be a leaf response path but still contain important production files; the operator must choose a genuinely disposable isolated location. Do not select a production application root merely because it appears in the settings.

## New evidence

A unique owned file is created with the known benign template bytes, its identity checked, its baseline stored in the normal canary table and its path temporarily enrolled in memory. Saved user settings and existing enrolled canaries are not modified. The file is reopened by identity and a benign byte changed. The normal scanner must generate a new `Canary integrity violation` incident containing the changed hash and controlled enrollment evidence. A genuine watcher notification is tracked separately from synthetic retries; a baseline-only or deferred-only observation is insufficient for the watcher check. The lab job never inserts that production canary incident or invokes the scanner directly.

The ordinary canary incident correlation uses a bounded reverse Security-log read, exact path and write mask, and refuses ambiguous writers. The lab uses a real pre-write Security watermark. Its writer is the existing service, not an external malicious process. The report requires a fresh record attached to the actual normal detector incident, the exact PID/image, a post-modification timestamp and the expected hash. The existing independent PowerShell probe remains separate. These checks do not prove attribution for an unplanned or adversarial incident.

The production target eligibility predicate is exercised against the actual audited service writer. It must refuse that writer. The lab does not call the termination API and never dispatches termination for its temporary canary. The actual production termination path retains its existing malware confirmation, process identity, explicit authorization, session-zero exclusion, engine pin, criticality and cancellation prerequisites. EICAR is harmless data, not a confirmed malicious running executable; it cannot establish positive malicious-process termination. Actual production termination remains Not tested, and the overall report is explicitly not certified. Do not relax those gates merely to get a green test.

The new temporary canary cleanup checks the original physical identity and known content hash before deleting; it removes only its own baseline row and resolves only its controlled finding after successful cleanup. Historical incidents remain available. On abrupt service or machine termination an orphaned test file/baseline may remain; review the reported exact path and remove only the known disposable artifact through authorized maintenance. No cleanup success is asserted without evidence. If normal watcher processing or audit correlation does not produce matching proof within the bounded observation, the report remains Review. If the optional lab fails to return checks, the missing results are explicitly marked untested or inconclusive.

The EICAR normal-scanner and sealed-receipt validation from V65/V66 is preserved. The report now shows an explicit production readiness assessment of controlled incident attribution, enrolled-canary watcher detection, EICAR quarantine and production process termination. The summary references the existing evidence rows without double counting. The final report can be exported as text.
