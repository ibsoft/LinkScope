# V49 — Local endpoint permission repair

## Why
The reported service is LocalService with unrestricted service SID. The Security channel descriptor does not explicitly authorize that SID, and no 4663 records were returned although File System success auditing is enabled. A folder SACL and an actual write are also necessary. The main service stays restricted.

## Install and use
1. Extract the complete source into a clean directory, rebuild using `Rebuild-VisualStudio.cmd Release`, and upgrade normally.
2. In Settings, save a narrow existing response directory under protected scope (prefer a disposable lab, not a whole production tree). For the user's test, keep `C:\Apache24` protected but authorize only `C:\Apache24\LinkScope-Ransomware-Test` for response. No mode or path is automatically changed.
3. Open LinkScope Setup > Endpoint permission repair. The local wizard runs after UAC, or invoke the built `LinkScopeSetup.exe --endpoint-permissions` from an elevated terminal. Select the exact response folder, Inspect policy, select individual repairs, and confirm. All options start unchecked. The wizard can grant Security channel read-only access to the service SID (not LocalService as a whole), a success audit rule for writes/deletes under the selected folder, and optional directory list/traverse/delete-child plus file read/delete rights. The last option is powerful: it affects descendants and can permit directory deletion, even though LinkScope's response policy is narrower. Select only a dedicated response folder. Existing inherited/explicit denials and protected child ACLs can still prevent effective access. Filename exclusion patterns cannot be represented by these inherited permissions. NTFS hard links can share ACLs outside the tree; do not apply on untrusted or linked trees. No recursive ACL rewrite command is used, but Windows may propagate inheritance. Do not select a whole user profile, drive root or system folder.
4. Audit policy is inspected, not changed. If Success is missing, have the administrator enable File System success auditing through the applicable local/domain policy. Security channel access covers the entire channel, not only 4663 records. No log clear rights are granted. A busy audited tree can generate large numbers of events; monitor log capacity and retention. Domain policy may override local changes.
5. Restart LinkScope if necessary (`Restart-Service LinkScope` from elevated PowerShell); this briefly interrupts monitoring. Open Endpoint > Test center > Run diagnostics. Readability and presence of 4663 events are separate results. Response path access remains advisory, not a guarantee of effective file quarantine.
6. Use `Test-LinkScopeContainmentLab.ps1 -LabRoot 'C:\Apache24\LinkScope-Ransomware-Test' -TerminateChild` in an isolated VM. Submit the printed marker within 30 seconds; verify matching 4663 and writer evidence. Keep production antivirus enabled. The local script terminates only its own child; this does not prove service-driven containment. To enable actual Contain policy, explicitly select mode and an eligible executable; a clean lab executable must never be treated as malicious. Process termination permissions are not granted by V49.

## Rollback
Backups are saved under `%ProgramFiles%\LinkScope Permission Backups` (admin/SYSTEM ACL). Each repair records its original and planned descriptor before modifying it and compares the readback. A partially completed multi-step repair is not atomic; prior successful changes can be rolled back separately. Choose Rollback in the wizard and select the JSON for the operation (newest first for overlapping changes). The wizard compares the current descriptor to the recorded one and checks NTFS volume/file identity; it refuses automatic rollback on conflict. Backups preserve the channel descriptor or selected ACL section, not individual descendant ACL snapshots. A missing SACL is represented by an empty SACL. Inheritance effects on independently modified descendants are not guaranteed to be reversible. If Windows normalizes the applied descriptor differently, the wizard stops for manual review rather than assuming success. Removing a response path from settings or uninstalling does not automatically undo Windows grants; use Rollback explicitly.

## Validation and limitations
Portable static and browser tests only; this environment cannot compile .NET Framework or exercise Windows Security channel, ACL inheritance, effective service access, UAC, or live containment. Native acceptance tests: inspect before/after descriptors, verify read-only SID ACE, verify successful 4663 under the lab, verify file read/delete access under the service identity, verify rollback and conflict refusal, verify no change to unrelated directories, and rerun Test Center. No changes to malware confirmation, response authorization, provider scheduling or detection thresholds.
