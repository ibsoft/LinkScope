# Endpoint Protection V66 — settings-driven test directories

All live Test Center exercises now use `Endpoint.TestPaths`, a saved list in **Settings → Endpoint Protection → Test Center directories (disposable folders only)**. Configure the intended test folder as a protected path and an explicit response path, then choose it in the new settings selector and save. This list is empty by default, including upgrades from older configurations without the property. No existing protection, response, exclusion, canary or termination policy is changed. No directory is created or granted permission by the new setting. Use dedicated disposable test folders in an isolated environment, never production application roots.

The settings editor can add eligible leaf response paths to the draft list. Server validation rejects actual files, paths outside exact saved response scope, exclusions and parents of another saved response path. Remove obsolete test paths when changing response scope. At runtime the selectors additionally require fresh service permission evidence for a directory; no arbitrary default or guessed fallback is used. One eligible test directory is automatically selected; multiple eligible directories require selection when there is no previous valid selection. Removing a directory or losing verification removes it from the test selectors. Backend audit, external writer and protection-lab endpoints independently require current saved test authorization, and native probe code retains its scope, identity and reparse safeguards. The advanced manual PowerShell command uses the selected path with literal quoting. The lab script installation location is unchanged; the script never selects a default test root.

Read-only diagnostics remain available without live test directory selection. The EICAR lab still requires explicit confirmation. No changes were made to detector logic, signature handling, quarantine verification or production containment evidence requirements.
