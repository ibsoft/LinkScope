# Endpoint Protection V31 — release candidate

## Evidence and scope
Based on V30 and the 27 November 2026 22:45:37 dashboard snapshot: online ClamAV, 259 clean signature checks, zero confirmed malware, 139 baseline checks, 33 queue entries, 156 historical deferred attempts, 74 consolidated outstanding coverage records, 76 active scan issues overall. Historical 30-second ClamD verdict timeouts occurred before the snapshot; root cause and installed binary identity are not independently established. The journal replay gap and old incomplete baseline warning remain real unresolved coverage issues. No blanket exclusions or threat alert suppression added; user profile, custom application roots, existing policy and canary checks preserved.

## Implementation
- Durable SQLite retry scheduling now stores consecutive attempt counts in a new additive table. Existing queue and retry timestamps are retained during migration. Failed attempts use 30, 60, 120, 240, 480, and up to 900 seconds between attempts. Duplicate deferrals during an active cooldown do not extend it. Acknowledgement removes pending work, priority metadata and both retry records atomically. Scope changes clean the old scope's retry records.
- Locked files no longer get a second in-memory retry loop. Ordinary watcher notifications, scheduled inspection and Downloads reconciliation honor the durable cooldown for that path. Dedicated canary integrity checks are not suppressed by this cooldown. Failed baseline entries are retained for real-time retry when enabled and queue capacity permits. A baseline file not inspected due to cooldown is counted as incomplete, never clean. Existing non-lock error paths may still create a short-lived in-memory retry record; watcher processing honors durable cooldown.
- Dashboard distinguishes deferred sharing violations from generic file scan errors, shows durable cooldown queue depth, labels priority entries (not unique arrivals), and separates unread alert counts. The historical finding identity is preserved.
- Deferred counters reset on policy changes consistently with other counters.

## Tradeoffs and limits
A repeatedly inaccessible path may wait up to 15 minutes for another automatic attempt, even if an ordinary watcher event arrives during cooldown. This reduces repeated disk and helper activity but increases potential detection latency after access becomes available. A current clean signature verdict is not inferred. No guarantee that the host's queue will catch up. The full baseline and the journal gap remain incomplete until successfully reconciled; USN events with unresolved parents are not discarded as benign. No changes were made to ClamAV engine deadlines, daemon configuration, ACLs, SACLs, or process attribution. V31 cannot establish why the engine timed out; use host diagnostics and ClamD logs to investigate. This is post-event monitoring, not pre-execution blocking. Keep primary AV enabled.
