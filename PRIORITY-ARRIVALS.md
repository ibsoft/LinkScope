# V17 — Priority scanning for downloads and new copies

Upgrade from V16 by extracting to a clean directory, running `Rebuild-VisualStudio.cmd Release`, then choosing Upgrade / repair in the installer. Preserve the existing configuration, ClamAV installation, SQLite state and canaries. No database migration or permission changes are required.

## Behavior

* A single bounded, case-insensitive watcher queue coalesces repeated events. Newly created files and rename destinations in any monitored directory are priority arrivals; paths containing a Downloads directory segment also receive priority. An additional newest-event slot helps with file overwrites. The ordinary queue cannot consume the final 1,024 entries of the 8,192-entry capacity; overflows still request reconciliation and are reported.
* Canary checks are scheduled first; priority watcher work is attempted before scheduled traversal or journal replay. Oldest queued work and full-scan progress receive dedicated slots. The existing one-second worker polling interval remains. These are scheduling targets, not a guaranteed maximum time to detection: an in-progress scan is synchronous and may delay subsequent work.
* Repeated writes extend the 750 ms quiet period (bounded by five seconds of waiting), and Windows sharing/lock violations receive up to three retries with 2, 4 and 8 second delays. A newer event arriving during a scan is retained. A journal entry associated with a scheduled retry is not acknowledged until the retry produces an attempted terminal result. Watcher retry timers are in memory; durable journal paths and checkpoints are unchanged. If ClamAV is offline, normal watcher work waits rather than being consumed without a scan.
* The journal reader's existing wire format and SQLite schema are unchanged. Pending journal work alternates oldest-first and recent-first batches (including Downloads). This helps fresh copies when the watcher cannot deliver their event, but USN replay still must reach their records and cannot guarantee immediate scans. A directory move that does not generate child events still depends on reconciliation. No file size, ACL, exclusion, reparse-point or response-scope restrictions have been relaxed.
* The dashboard live counts include Priority arrivals. Live file scan activity lists verdicts including Infected, Clean, Missing, Failed and Limited. A sharing violation includes retry diagnostics. Coverage gaps remain visible. Missing files and access denied do not mean malware was detected or that a file was clean.

## Windows acceptance checks

1. Ensure both LinkScope services are running, ClamAV is online, real-time monitoring is enabled, and Downloads plus a controlled copy destination are within active scan scope and not excluded. Keep Monitor mode for the test. Verify the service identity has read access to the relevant files. Do not change the ACL of the entire user profile or Windows drive.
2. Download the official harmless EICAR test file, if your organization's policy permits. Do not disable your primary antivirus to force a test; ESET or the browser may intercept it before it reaches LinkScope. Verify it actually exists on disk. Check Live file scan activity and Alert history for the ClamAV verdict; a confirmed EICAR signature should generate an individual malware finding.
3. While a scheduled scan is running, copy a harmless test file into a monitored directory (for example C:\unx or D:\test if included), then rename another test file into its final name. Confirm both paths appear in live scan activity. Repeat by overwriting a file and after holding a file open for writing; verify the final content receives a scan attempt. Test separately from the active system drive if possible.
4. Check the Priority arrivals metric and the watcher/USN backlog. Existing canaries, coverage warnings and other historical incidents must remain intact. If a download disappears before a verdict, check the primary antivirus quarantine history. If access is denied, use a monitored, readable test directory and review narrowly scoped permissions.
5. Optional native fixtures: run `LinkScope.exe --usn-self-test` from an elevated terminal after building. Includes synthetic USN parser, pipe timeout and priority queue checks. Does not test an actual file download or ClamAV detection.

## Validation performed

Portable tests: priority arrival source wiring and actual SQLite ordering against 3,000 old paths, scheduling source/model checks, journal durability, endpoint scope and alert preservation, coverage aggregation, endpoint/build/config checks, JavaScript activity checks, canary setup and USN transport source checks. Native Windows compilation and EICAR detection have not been executed in this environment. No scan latency measurement has been made.
