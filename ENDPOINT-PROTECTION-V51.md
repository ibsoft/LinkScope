# V51 — Setup preflight and ClamAV readiness repair

## Installation self-check
V50 installation could fail at the native check named `upgrade preserves existing scope and policy except migration marker`. The assertion compared two whole JSON strings, an unnecessarily fragile comparison because serialization order is not a policy invariant. The exact reason for the reported Windows failure has not been reproduced. V51 retains the self-check and compares every public EndpointSettings property by value, cloning array values before migration. Only ProfileDefaultsApplied may change; its final value is asserted. The migration is exercised twice to check idempotence. Failures now name the specific property. The migration itself is unchanged, so there is no automatic profile or canary enrollment. The worker's setup preflight still precedes configuration initialization and service deployment.

## ClamAV readiness
The installer previously ran a non-elevated check before install and after operations, potentially overwriting a successful elevated check with code 13 (private configuration). V51 uses an elevated preflight when a prior check was elevated or code 13 was received, and rechecks after ClamAV operations with elevation. UAC approval is still required; an additional prompt may occur. Private configuration remains private. No ACL, provider credentials or maintenance rate limits are changed.

Setup, update worker and endpoint telemetry share the official loaded-definition timestamp parser. ClamD VERSION is authoritative for loaded freshness. Its 72-hour threshold is retained. The installer records the loaded version, definition age, and advisory daily.cvd/daily.cld header versions in its existing administrator-only log. A header is not a signature validation and is not sufficient to mark the engine current. A newer archive on disk prevents a green readiness result until the loaded version is confirmed. An unchanged stale archive requires an actual update, not merely a reload. Updater service/startup failure is distinguished from a stale date. The signature worker waits up to approximately two minutes for a reload to settle (individual command and service timeouts still apply), without launching repeated downloads; it distinguishes official update failure, pending reload, and stale definitions. Provider-specific persistent cooldowns and global 60-minute manual cooldown remain in place. Configure/repair is not suggested solely for stale definitions; use Update signatures when eligible. FreshClam's ordinary automatic updates are unchanged.

Reference: ClamAV documented VERSION protocol and CVD archive header: https://docs.clamav.net/manual/Usage/ClamdProtocol.html and https://docs.clamav.net/manual/Signatures.html

## Install and verify
Extract the complete source into a clean folder and run Rebuild-VisualStudio.cmd Release. Run the new setup executable and approve UAC. For an optional direct native preflight, run the newly built LinkScope.exe --self-test from an elevated terminal; this also runs additional account checks. If setup still fails, inspect the latest administrator log in C:\Program Files\LinkScope Setup Logs. For ClamAV click Check again, approve UAC, and inspect the latest check-clamav log. A green check requires a verified standard engine, current loaded definitions, and running/automatic updater services. V51 cannot force remote signature availability, bypass provider restrictions, or certify Windows execution in the build environment.

## Verification limits
Portable targeted tests and browser fixtures are recorded in ENDPOINT-TEST-RESULTS-V51.txt. No Windows native compiler/runtime, actual UAC, service installation or live FreshClam reload was exercised. The full historical regression suite was not run. Existing permission repair and containment policies are not changed.
